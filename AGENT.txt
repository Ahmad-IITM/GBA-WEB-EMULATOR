ARCHITECTURE CHANGES
==============================================================================

THREE INDEPENDENT PIPELINES:

1. Game Loop (frame)
   - Runs ~60 FPS via requestAnimationFrame
   - Calls _mgba_web_run_frame()
   - Renders to canvas (drawFrame)
   - No blocking from other operations

2. Audio Loop (audioFrame)
   - Independent RAF timer
   - Pulls audio samples via pullAudio()
   - Maintains audioQueue for ScriptProcessor
   - Continues even if game rendering stalls

3. Save/State Loop (saveStateFrame)
   - Independent RAF timer
   - Processes one task per frame from saveStateQueue
   - Handles save: extracts state from core
   - Handles load: validates ROM ID, loads to core
   - No blocking on main loop

==============================================================================
TECHNICAL NOTES
==============================================================================

- ROM ID uses first 16 bytes of ROM file (GBA header region)
- State ID uses last 16 bytes of state file (trailer or footer region)
- This prevents loading states from wrong ROMs
- Audio buffer 16384 = ~372ms at 44.1kHz (2x improvement over 4096)
- Save/State operations queue up, execute one per frame (~16ms apart)
- No synchronous blocking - all async with Promises
